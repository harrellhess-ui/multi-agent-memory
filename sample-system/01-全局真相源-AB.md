6. **尺寸上限只约束全局记忆**：各份全局文件**每份不超过 400 行**（软上限）——超限时**优先删重复与过时条目**，不得靠追加新条突破；**项目侧文件不设全局尺寸上限**，由项目自身约定。

## 启动自检

各 Agent 的启动链统一为**六步共同核心**，顺序固定：

1. 称呼 **AB**。
2. 确认当前工作目录和项目根目录。
3. 读取全局真相源 —— 本文件 `C:\Users\Demo\.agents\AB.md`。
4. 读取本 Agent 的全局适配器（Claude → `.claude\CLAUDE.md`，Codex → `.codex\CODEX.md`，
   DSH → `.dsh\DSH.md`）；两个原生壳 `.codex\AGENTS.md` / `.dsh\AGENTS.md` 由平台
   自动加载，不重复读。
5. 读取项目侧 —— 先读共享的 `PROJECT_CONTEXT.md`；本 Agent 项目适配器的读取、
   创建和维护按本 Agent 全局适配器执行。
6. 按需读取跨 Agent 文件 —— 只在维护对方制度、处理跨 Agent 冲突或修改对方文件时，
   才读对方的项目适配器。

**加载链异常守则**：本文件未生效、目标文件缺失、`.agents` Git 追踪数不符或出现
ReparsePoint 时，先报告并**停止修改全局制度**，待修复后再改。

**启动回执**：审计加载链时，在上述读取与冲突检查完成后输出一次回执；冲突尚未检查
时标注 `Conflicts: pending`。

> 各 Agent 适配器可在此基础上**增补平台专属步骤**，但**不得删减或重排**上述共同核心。

## 收尾流程

当说"收工""收尾""撤了""下了""结束""散会"时，按以下流程执行，不可跳过：

**一、并行同步（顺序不限，全部完成后再进入总结）**

- 同步全局真相源 — 新增、移除或更名项目 → 本文件项目树；项目状态与进度 → 对应 `PROJECT_CONTEXT.md`；配置变化 → 技术环境段或对应 Agent 全局适配器
- 同步项目入口 — `PROJECT_CONTEXT.md` 与本 Agent 项目适配器有变动 → 按各自职责更新；跨 Agent 文件只在相关任务中处理
- 多文件一致性检查 — 对比各份全局文件的共同启动核心、收尾触发和收尾入口；各全局适配器各自维护本 Agent 的项目适配器规范，不要求内容一致。原生壳只比启动自检；另核验各份全局文件均无 `## 变更记录`（维护规则 5）——⚠️ **核验须排除代码围栏内的模板字面示例**：三份适配器都可能载有「项目适配器模板」，其中的 `## 变更记录` 是**示例、不是真章节**。**用行号判断是否落在围栏内，勿用裸 grep 计数**
- 收尾流程 — **先尺寸体检**（全局记忆超 400 行、或项目真相源与适配器明显膨胀时，**先精简、后补漏**），再清理过时文档、重复记忆、临时文件；编辑一律遵循**减优于加、合并优于追加、删除优于保留、绝对时间戳**四条原则。详细步骤读取 `C:\Users\Demo\.agents\收尾流程.md`
- Git 提交 — **全局文件**有变动 → 提交 `.agents` 仓库；**项目文件**有变动 → 提交对应项目仓库

**二、统一总结（只讲一次）**

按本人偏好选择风格与篇幅。要求：

- **每条战线展开叙述**：背景（为什么做）、过程（怎么做的、关键决策点）、结果（改了什么文件）、评价（这一步的价值）
- **有细节有判断**：不是"改了 A 文件"这种流水账，而是"改了 A 文件第 X 行，从旧表述改成新表述，为什么这样改，跟哪个真相源对齐"
- **总结末尾**：口头汇报变更清单（完整路径 + 一句话摘要；无变更则声明）
- **未处理项**：把 `PROJECT_CONTEXT.md` 与项目适配器的矛盾、无法自动判断的事项、需本人定夺的取舍**逐条摆出**，不得隐藏

⚠️ **不汇报变更清单 = 白干。下次新会话不知道改了什么。**

> 风格、称呼、总结长度都是**可选个人偏好**，不是机制的一部分。你可以完全不要这一节，或换成"简短汇报"。

## 新建项目规范

长期项目必须建立 `PROJECT_CONTEXT.md`，作为项目共享事实、当前状态和跨 Agent 决策的

### PROJECT_CONTEXT.md 最小框架

文件标题为 `# <项目名称> · 项目共享上下文`，按以下顺序建立二级章节：

| 章节 | 内容 |
|---|---|
| 项目目标 | 要解决的问题、工作范围与预期交付物 |
| 目录与稳定事实 | 项目根目录、代码与资料的实际路径、技术栈及关键入口 |
| 当前状态 | 已完成、进行中和阻塞事项；验证结果注明日期与证据位置 |
| 已确认决策 | 本人确认的方案、约束和跨 Agent 约定 |
| 下一步 | 可执行的后续任务、前置条件与待确认事项 |
| 验证方式 | 共用的运行、测试或人工验收方法，写清执行目录与通过条件 |
| 变更记录 | `YYYY-MM-DD` 加一句变更摘要，详细过程归专项文档或 Git 历史 |

按需增加"技术参考""证据索引""结论边界"等章节。未知信息标为待确认，不编造完成状态；
Agent 专属操作规则归各自适配器。既有项目可沿用语义等价的章节名，不为套模板重排全文。

`CLAUDE.md`、`CODEX.md`、`DSH.md` 等项目适配器的建立、读取和维护规范，分别由对应
Agent 的全局适配器负责；本文件不重复规定。新增、移除或更名长期项目时同步本文件项目树。
