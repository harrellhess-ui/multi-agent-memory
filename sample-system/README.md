# 脱敏样本：真实系统长什么样

这里的文件来自**作者本机长期在用的真实机制**，做了脱敏处理。

用途只有一个：**回答"我搭的这个对不对"**。它能让你对照真实系统的目录结构、文件职责划分、
每份文件的篇幅和写法。

---

## 脱敏做了什么

| 原值 | 样本中的值 |
|---|---|
| 真实用户名 / 称呼 | `AB` |
| 真实主目录 `C:\Users\<真名>` | `C:\Users\Demo` |
| 全局真相源文件名（用真名命名） | `AB.md`（自定义名；**发行版默认名是 `ME.md`**） |
| 真实私人项目路径 | `D:\Projects\proj-a` 等虚构路径 |
| 机器软件环境、版本、插件清单 | 泛化为占位说明 |
| 收尾流程相关内容 | 改为"读取 `收尾流程.md`"，**已按本发行版去掉技能机制** |

**结构、职责划分、启动链、维护规则、收尾触发全部保留**——这些才是机制。

> ⚠️ 本样本与真实原件有一处**刻意的差异**：作者本机把收尾流程做成了平台技能，
> 本发行版**已改为普通 Markdown 文件 + 全局文件里一行引用**。
> 样本按发行版口径写，不按作者本机现状写——否则你会照着搭出一个多一层依赖的系统。

> 📌 **文件名说明**：样本里全局文件叫 `AB.md`，那是**自定义命名**的演示。
> **发行版的默认名是 `ME.md`**，你自己搭的时候用默认名就行，不需要跟着样本改成 AB。
> 文件名本身不影响机制——它只是个名字，定了别改即可。

## 四份样本的对照价值不同，看的时候注意

| 文件 | 保真度 | 看什么 |
|---|---|---|
| `01-全局真相源-AB.md` | **原文脱敏** | 全局文件该有哪些章节、维护规则怎么写、启动六步的顺序、收尾怎么指向流程文件 |
| `02-Claude全局适配器.md` | **原文脱敏** | 适配器怎么当原生入口、**内嵌的项目适配器模板**长什么样 |
| `03-Codex原生壳-AGENTS.md` | **原文脱敏** | 原生壳为什么只写几行、什么端需要壳什么端不需要 |
| `04-项目共享上下文-骨架.md` | **骨架，非原文** | 七章节各写什么。原文件 300+ 行且含私人项目内容，不适合整体脱敏 |

第 4 份是骨架，文件里已在开头明确标注——**别把它当成原文样本**。

## 怎么用

搭完之后，拿你生成的文件和这些样本对比：

1. **文件数量对不对**？接了 N 个端就该有对应的文件数，见 `../文件结构.md` 第二节
2. **职责划分对不对**？检查你有没有把项目状态写进适配器、把 Agent 专属规则写进全局文件
3. **篇幅对不对**？全局文件几十到两百行量级；如果某份适配器涨到几百行还全是项目历史，就是没归位
4. **启动链顺序对不对**？全局真相源 → 本端全局适配器 → 项目上下文 → 本端项目适配器
5. **收尾接上了没有**？全局文件里有没有写明 `收尾流程.md` 的绝对路径

第 3 条最容易被忽略：**适配器堆积项目流水账**是这套机制最常见的失败方式，
收尾时的核心工作就是把它归位。
