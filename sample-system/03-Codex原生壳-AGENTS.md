# AB · Codex 原生启动入口

本文件由 Codex 自动加载，只负责启动引导，不承载完整制度。
1. 每条回复称"AB"，并确认当前工作目录和项目根目录。
2. 读取全局真相源 `C:\Users\Demo\.agents\AB.md`。
3. 读取 Codex 全局适配器 `C:\Users\Demo\.codex\CODEX.md`。
4. 按全局适配器读取项目 `CODEX.md` 和 `PROJECT_CONTEXT.md`。
5. 文件和实时证据始终优先于 Codex memories。
6. 若本文件未生效、目标文件缺失、Git 追踪异常或出现 ReparsePoint，先报告并停止修改全局制度。

## 为什么要分两级

| | 平台自动加载 | 谁读 |
|---|---|---|
| 原生壳 `AGENTS.md` | 是 | 平台 |
| 全局适配器 `CODEX.md` | 否 | 原生壳第 3 条让 Agent 去读 |

**好处**：制度正文不放在平台自动加载的文件里，平台改加载规则时你只需要改壳，制度不用动。

**代价**：多一跳。壳没生效时 Agent 就读不到制度——所以壳里第 6 条专门写了"未生效先报告"。

## Claude 那边为什么不这样

Claude Code 的 `~/.claude/CLAUDE.md` **本身就是平台自动加载的**，所以那一个文件同时当原生入口和适配器用，不再套一层壳。

**判据**：一个端需不需要壳，看它有没有"平台会自动加载的那个文件"。

- Claude：`~/.claude/CLAUDE.md` 自动加载 → **不需要壳**
- Codex：`~/.codex/AGENTS.md` 自动加载 → 制度放 `CODEX.md`，**需要壳**
- DSH：`~/.dsh/AGENTS.md` 自动加载 → 制度放 `DSH.md`，**需要壳**

## ⚠️ Codex 特有的一步：项目适配器要配 fallback

Codex 默认**不会**自动发现项目根目录的 `CODEX.md`。必须在 `config.toml` **顶层**加：

```toml
project_doc_fallback_filenames = ["CODEX.md"]
```

注意三点：

1. 必须在**顶层**，不能塞进任何 `[section]` 里
2. 已有这个键就**合并数组**，不要重复定义键
3. 项目里同时存在 `AGENTS.md` 时会影响入口选取——保留原仓库规则，在**实际生效的那个入口**里补上读取要求
