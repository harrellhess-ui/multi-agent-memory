# 多 Agent 个人记忆机制

一种面向本地个人开发者的多 Agent 记忆管理机制。

把一个开发者同时使用的多个编码 Agent（Claude Code / Codex / DSH 等）接到同一套
**落在磁盘上、可读可改可 Git 追踪**的记忆文件上。

不是平台、不是网页面板、不需要数据库或额外模型 API。

---

## 直接复制这段给你的 Agent

先把这个仓库 clone 或下载 ZIP 并解压，然后**整块复制**下面这段，粘给你的编码 Agent：

```text
我下载了一个叫「多 Agent 记忆机制」（multi-agent-memory）的东西，
想用它来管理我和多个编码 Agent 之间的长期记忆。

请你自己把这个包找出来并读完：
1. 先定位这个包在磁盘上的位置。我记不清具体路径，你可以在我的下载目录、
   桌面、或其他常见位置搜索名字含「multi-agent-memory」的文件夹
   （也可能显示为「多Agent记忆机制」的说明标题）。
   找到多个就停下来问我；一个都没找到就告诉我，让我手动给你路径。
2. 读完包里这三样：
   - README.md
   - 记忆机制与部署.md      ← 主体，重点读第 0 节、第 8 节
   - 收尾流程.md            ← 收尾流程正文，要复制到固定位置
   sample-system/ 是脱敏样本，用来对照，不影响部署，可以先不看。

然后按 `记忆机制与部署.md` 第 0 节帮我部署：
- 要问我的问题一次问完，别挤牙膏式来回。
- 我没答的项你用默认值，最后明确告诉我你替我定了哪些。
- 动任何文件之前，先把「要建哪些文件、分别放哪」列成计划给我确认。
- 已有文件不要覆盖，先备份再合并。
- 我原来的规则文件和原生记忆都不要动，也不要迁移。
- 不要提交 Git、不要推送。

部署完（含收尾流程文件放好、全局文件里写明它的路径）之后，按第 8 节教我怎么用收尾：
说哪些词能触发、说完会发生什么、我怎么自己验证它真的生效了。最后按第 0.7 节给我五段报告。
```

**没解释清楚的地方就是包的错**，把 Agent 的原话发到 Issue 里。

> ⚠️ **关于仓库名（维护者注意）**：仓库名必须是 **ASCII 英文** `multi-agent-memory`。
> GitHub 会**静默剥掉仓库名里的非 ASCII 字符**——本仓库最初命名为 `多Agent记忆机制`，
> 结果被创建成 `-Agent-`，下载出来的文件夹叫 `-Agent--main`，上面提示词的搜索词就失效了，
> 使用者的 Agent 第一步就找不到文件。
> 上面提示词里的搜索词 **`multi-agent-memory` 必须与仓库名保持一致**，改一个就要改另一个。

## 三种用法

**① 让 Agent 自己看（就是上面那段，推荐）**

**② 自己读**

打开 `记忆机制与部署.md`。完整自包含：机制说明 → 从零搭建 → 日常使用 →
跨 Agent 交接 → 收尾 → 验收方法。三端（Claude / Codex / DSH）都有可复制的原件级片段。

**③ 看真实系统长什么样**

`sample-system/` 是作者本机在用的机制，**脱敏后的样本**。
用途是回答"我搭的这个对不对"——对照目录结构、文件职责划分、每份文件的篇幅。

## 包内文件

| 文件 | 是什么 | 给谁 |
|---|---|---|
| `记忆机制与部署.md` | **主体文档**。机制说明 + 部署教程 + 收尾说明 + 验收 | Agent 和人都读 |
| `收尾流程.md` | **收尾流程正文**，部署时复制到固定位置，并在全局文件里写明路径 | Agent 用，人了解 |
| `文件结构.md` | 磁盘上实际长什么样：目录树、每份文件职责、哪些该进 Git | 人读 |
| `sample-system/` | 脱敏样本：全局真相源、Claude 适配器、Codex 原生壳、项目上下文骨架 | 人读，对照用 |

**没有技能文件，也不需要。** 收尾是一套流程步骤，靠"一个 Markdown 文件 + 全局文件里一行引用"
接上——不需要技能发现机制、不注册斜杠命令、不随平台版本失效。这是刻意的设计。

## 这套机制解决什么

- **多个 Agent 各记各的** → 共享一个全局真相源，长期规则只有一份
- **换个 Agent 就断片** → 项目状态落在项目目录的文件里，谁接管都读得到
- **Agent 记的"事实"是错的** → 文件和实时证据是权威，模型自动记忆只是辅助
- **不知道哪条记忆过期了** → 每条信息有唯一归属位置，收尾时按位置核对
- **改了什么没人知道** → 全在 Git 里

## 它不解决什么（先说清楚）

- **不做语义检索**。全局和项目文件是整份注入的，靠"写得精、码得住"成立。
  知识长到塞不进上下文时，这套机制没有 recall 层。
- **不做自动冲突解决**。两个 Agent 同时改同一文件，合并靠人。
- **不做跨设备同步**。默认单机个人使用。
- **新鲜度靠人**。没人按时收尾，文件会漂移、膨胀、互相矛盾，机制不会自己发现。
- **成本是人的勤快**。一个人好用，一个团队会崩。

## 状态与限制

- **这套机制是作者长期在用的**：文件分层、启动加载、收尾归位、跨 Agent 交接都在真实项目里跑过。
- **但这份文档本身没有在干净环境里按自己的步骤复跑过**。文档够不够陌生读者一次搭起来，
  作者无法替你保证。
- **"丢给 Agent 自动部署"这条路径（第 0 节）和"教使用者用收尾"（第 8 节）都没有真实运行记录**——
  它们是按这个用法新写的。
- **许可**：[MIT](LICENSE)。可以放心使用和再分发。

所以：**照着做的时候，遇到说不通、找不到、行为与描述不符的地方，那不是你不会用，
多半是文档漏了东西。这类问题请回报，比"能不能跑"更有价值。**

## 最短路径

```text
1. clone 或解压
2. 复制上面那段提示词给 Agent
3. 回答它问你的问题
4. 确认它给的放置计划
5. 按第 8 节学会说"收尾"
6. 开一个全新会话，验证它能说出项目目标、决策、下一步和收尾流程文件路径
```

前四步十分钟内能做完。**第五步是关键——新会话答不上来，就是没接好。**
